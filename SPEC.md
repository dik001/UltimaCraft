# Спецификация Database Builder + Database Viewer

## 1. Назначение

Локальное desktop-приложение предназначено для ручного создания, поддержки и просмотра большой связанной базы игровых предметов. Первая версия не рассчитывает себестоимость и цепочки крафта, но хранит данные так, чтобы отдельный Craft Engine мог быть добавлен позже без переделки основных сущностей.

Главные приоритеты: сохранность данных, целостность связей, удобный массовый ввод, корректное разграничение режимов, быстрый поиск, быстрое обновление рыночных цен и только затем визуальные улучшения.

## 2. Технологии и хранение

- Python 3.12+ (поддерживается Python 3.11 при наличии совместимых зависимостей).
- PySide6 для desktop UI.
- SQLite: `data/database.db`.
- SQLAlchemy ORM 2.x.
- Alembic для версионирования схемы.
- Изображения — файлы в `data/images/items/`, в БД — относительный путь.
- Резервные копии — `backups/database_YYYY-MM-DD_HH-MM-SS.db`.
- Логи — `logs/app.log`.
- Интерфейс полностью на русском языке и работает без интернета.

## 3. Режимы

### Администратор

Может создавать, редактировать, дублировать и безопасно удалять предметы; управлять справочниками; создавать несколько рецептов результата; редактировать ингредиенты, требования, награды, оборудование, способы получения и цены; загружать/заменять/удалять изображения.

### Пользователь

Игровые данные доступны только для чтения. Скрыты административные действия. Разрешено быстро менять текущую цену аукциона с немедленным сохранением и отображением времени обновления. Переключение в режим администратора защищено локальным паролем настройки; сложная система аккаунтов не создаётся.

## 4. Сущности и правила

- `CraftStation`: название, описание, порядок, активность.
- `ItemGroup`: название, порядок.
- `ItemSubgroup`: принадлежит группе, название, порядок.
- `Item`: название, группа, опциональная подгруппа, ранг, класс, путь изображения, заметки, активность, признак используемого предмета, даты.
- `ItemUseEffect`: тип эффекта, числовое значение, максимальное число использований. Модель допускает несколько типов эффекта.
- `Recipe`: результат (`Item`), станция, выход за крафт, энергия, заметки, активность, даты. У предмета 0..N рецептов.
- `RecipeIngredient`: рецепт, существующий `Item`, количество. Текстовые ингредиенты запрещены; пара рецепт/ингредиент уникальна. Если администратор вводит новое имя в строке ресурса, перед сохранением он выбирает группу/подгруппу, после чего приложение атомарно создаёт полноценный `Item` и связывает его ID с рецептом.
- `Skill`: справочник навыков.
- `RecipeSkillRequirement`: рецепт, навык, требуемый уровень; пара уникальна.
- `RecipeSkillReward`: рецепт, навык, опыт; пара уникальна.
- `Equipment`: справочник оборудования и опциональное изображение.
- `RecipeEquipmentRequirement`: рецепт, оборудование, количество; пара уникальна.
- `AcquisitionMethod`: справочник кодов `FIND`, `TRADER`, `AUCTION`, `CRAFT`.
- `ItemAcquisition`: M:N между предметом и способами. Один предмет поддерживает несколько способов одновременно.
- `ItemPrice`: предмет, расширяемый тип цены, неотрицательная цена и время обновления. Минимум `TRADER` и `AUCTION`, пара предмет/тип уникальна.
- «Используется в крафтах» вычисляется по наличию `RecipeIngredient`, отдельной ручной истины нет.

Деньги, энергия, эффекты и опыт хранятся как фиксированные десятичные значения. Количества также допускают дробные значения. UI не показывает незначащие `.0`.

## 5. Валидация и целостность

- Название предмета обязательно.
- Выход рецепта и количество ингредиента/оборудования больше нуля.
- Энергия, уровень, опыт и цены неотрицательны.
- Для используемого предмета нужен хотя бы один эффект, положительное число использований и непустой тип эффекта.
- Подгруппа предмета обязана принадлежать выбранной группе.
- Один ингредиент, навык или тип оборудования не дублируется внутри соответствующего списка рецепта.
- Введённое имя ингредиента никогда не использует скрытый ID ранее выбранной строки. Точное существующее имя разрешается в его ID; отсутствующее имя проходит quick-create.
- Предмет-результат разрешено использовать как ингредиент собственного или другого рецепта. Будущий Craft Engine обязан обнаруживать циклы графа.
- Внешние ключи SQLite включены на каждом соединении.
- Удаление используемых справочников и предметов блокируется понятным сообщением.
- Рецепт и его собственные строки могут удаляться как единый агрегат только после явного подтверждения; удаление предмета не каскадирует на чужие рецепты/ингредиенты.
- Редактирование карточки сохраняется только по кнопке. Быстрая цена в Viewer сохраняется по Enter.

## 6. Основной интерфейс

Главное окно содержит верхнюю панель с заголовком, поиском, кнопками создания предмета/рецепта, справочников и переключения режима; слева — дерево групп, подгрупп и предметов; справа — прокручиваемая карточка.

Карточка предмета содержит:

- изображение с preview, выбором файла, вставкой скриншота из буфера обмена, заменой и удалением;
- основные поля;
- свойства использования;
- несколько способов получения и раздельные цены;
- 0..N редакторов рецептов;
- динамические строки ингредиентов, требований навыков, наград и оборудования;
- `Сохранить`, `Сохранить и создать следующий`, `Отменить`, `Дублировать`, безопасное удаление.

Для быстрого ввода значения группы/подгруппы и последней станции сохраняются в текущем сеансе для следующего нового предмета. Рецепты и цены без явного дублирования не переносятся.

В строке ингредиента можно выбрать существующий Item или напечатать новое название. Все новые названия собираются в один компактный диалог классификации. Группа и подгруппа в нём редактируемы: точное безрегистровое совпадение выбирает существующий справочник, а отсутствующее имя создаёт новую запись. Новые группы, подгруппы, предметы и рецепт сохраняются одной транзакцией; при ошибке или отмене частичные данные не остаются в базе.

В режиме администратора рядом с preview доступна кнопка `Вставить скриншот`. Локальный `Ctrl+V` работает при фокусе на области изображения и не перехватывает вставку текста в полях. Изображение из буфера становится несохранённым preview и копируется в `data/images/items/` только вместе с сохранением карточки.

## 7. Поиск и фильтры

Регистронезависимый поиск по названию, группе и подгруппе. Фильтры: станция, группа, подгруппа, ранг, класс, возможность крафта, способы `TRADER`/`AUCTION`/`FIND`, использование как ингредиента. Запросы выполняются БД; предусмотрены индексы на поисковых и внешних ключах.

## 8. Справочники

В административном разделе доступны CRUD для станций, групп, подгрупп, навыков и оборудования. Значения выбираются из БД, игровые справочники не хардкодятся в UI.

После изменения справочников открытая карточка обязана обновить варианты во всех существующих строках рецепта без пересоздания черновика. Текст, совпавший с только что созданной записью без учёта регистра, должен разрешиться в её реальный ID.

## 9. Надёжность и сервисные функции

- Подтверждение важных удалений.
- Потерянное изображение заменяется placeholder без падения.
- Пользовательская ошибка показывается в диалоге. Неожиданная техническая ошибка показывает свой тип и сообщение, а полный traceback записывается в `logs/app.log` до показа аварийного окна.
- `Файл → Создать резервную копию базы` использует безопасный SQLite backup API.
- `Файл → Открыть папку данных` открывает локальный каталог.
- Экспорт/импорт JSON допустим как дополнительная функция после основной готовности.
- При закрытии карточки с несохранёнными изменениями приложение предупреждает пользователя.

## 10. Визуальный стиль и размеры

Интерфейс строится как современный dashboard: постоянный левый сайдбар с каталогом и режимом доступа, компактная верхняя строка поиска и действий, отдельная карточка фильтров и спокойные скруглённые панели контента. Основа — тёмный фиолетово-графитовый фон; градиент бренда и основные действия используют фиолетовый, розовый и бирюзовый из выбранной палитры, а жёлтый/оранжевый остаются вспомогательными акцентами. Подписи полей, обычный текст, подписи чекбоксов и служебные layout-контейнеры всегда имеют прозрачный фон — отдельные прямоугольные подложки под текстом запрещены. Собственная подложка остаётся у панелей, кнопок и полей ввода. Целевой размер 1920×1080; интерфейс остаётся доступен при меньшем окне, правая карточка прокручивается только вертикально.

## 11. Явно вне первой версии

Расчёт цепочек и себестоимости, выбор «купить или скрафтить», прибыльность, оптимизация и планирование, дерево производства, парсер цен, сервер, облачная авторизация и мобильное приложение.

## 12. Критерий готовности

Без программирования пользователь может создать все справочники, предмет с изображением/эффектами/несколькими способами и ценами, сложный рецепт с реальными предметами-ингредиентами, найти и отфильтровать его, перейти в Viewer, убедиться в read-only игровых данных, изменить аукционную цену и после перезапуска увидеть сохранённые данные. Резервная копия создаётся и открывается как целостная SQLite БД.
